# 2026-10-02 FTMO Griff live-rules backtest: BTC 1H inside-bar, US100 NY session, Gold Asian range

Run date: 2026-10-02. Repo commit the live code was read from: `a77ec1b950d7873c5e4e58e3833ee6255a927e26` (`main`).
Everything in this folder is a backtest artifact. Nothing here changes live risk, configs, or engine behaviour, and nothing was deployed.

## One-line answer

On this history (2024-01 to 2026-08, 32 complete calendar months), Stack B makes a +10% calendar month **less** likely than Stack A: 1 of 32 months at Stack B vs 5 of 32 at Stack A, while Stack B cuts the realized max drawdown from -36.1% to -19.0%, the worst day from -5.48% to -2.77%, and the count of <= -10% months from 4 to 0.

## Question

At the LIVE rules of the three FTMO engines, what does a month look like at two risk stacks, and would either clear a 10% profit month.

| Stack | BTC | US100 | Gold | Status |
|---|---:|---:|---:|---|
| A | 0.80% | 1.00% | 0.50% | current live code (see LIVE CODE) |
| B | 0.25% | 0.50% | 0.25% | proposed, NOT approved, not in code |

Equity base: one shared FTMO account starting at **$100,000**. Position size is recomputed per trade from the realized account balance at entry using each engine's own live sizing formula (compounding).

## LIVE CODE (what the engines do; read, not modified)

### BTC: `griff_engine_live.py` (symbol `BTCUSD`)
- Risk: `self.risk_pct = 0.0080` when `symbol == "BTCUSD"` (L474-475). Sizing: `calculate_position_size` (L211-254): `lots = round(equity*risk / (1.5*ATR14 * tick_value * contract_size), 2)` clamped to [0.01, 50]. Contract size 1, tick value 1 (`data/ftmo_asset_specs.json`).
- Timeframe/window: completed 1H candles, `fetch_completed_1h_candles(limit=60)` (L1249); setup scan requires 50 bars (`MIN_CANDLES_FOR_SETUP_SCAN = 50`, L51).
- Setup: `is_inside_bar(candles[-1], candles[-2])` (L196-208, strict `<`/`>`). Direction = BUY if close > `compute_ema_50` (L153-162, seeded EMA over the last 50 closes) else SELL (L1336). Filter: `compute_adx(candles, 14)[-1] >= 25` (L115-151, L1343).
- Orders: one pending stop in the trend direction at the inside-bar high (BUY) or low (SELL), stop loss = 1.5 x ATR14 (`compute_atr_14` = SMA of last 14 true ranges, L85-111; `calculate_initial_stop_loss`, L257-273). No take profit (L1051-1070).
- Pending expiry: if the latest completed bar is no longer the setup bar, the pending is cancelled (L1312-1328), i.e. the fill window is the single bar after the inside bar.
- Trailing: on each new completed bar, `calculate_structural_trailing_stop` (L164-193): long SL ratchets to `c2.low - 0.5*ATR14` when `c2.low < c3.low and c1.low > c2.low`; mirror for shorts. Exit only via the stop.
- Also in code but not simulated: 90% free-margin lot cap (L1023), hard equity floor $90,000 and 5% daily-loss halt (L464-465, L718). See BACKTEST / proxies.
- Note: the same file sets `US100.cash` to 0.0065 for the 1H engine (L473). That is a different engine from the US100 NY session engine below and is not part of this question.

### US100: `griff_engine_us100.py` (symbol `US100.cash`)
- Risk: `risk_pct = float(cfg.get("risk_pct", 0.01))` read from `config_us100.json` (L69). That file is gitignored (`.gitignore` L6), so the value actually running on the VM is **UNKNOWN from this repo**; Stack A uses the code default / stated live value of 1.00%.
- Window: 15m candles via `get_historical_candles(mt5_sym, '15m')` with no limit (L131); needs > 25 candles.
- Entry window 09:45-11:30 ET (L347). Trend from the last completed candle: `prev.close > ema[-2]` -> BUY else SELL (L357; `compute_ema` L111-121 is a seeded EMA20). Trigger: `ask <= current_ema` (BUY) / `bid >= current_ema` (SELL) where `current_ema = ema[-1]` includes the forming candle (L366-371). Market order at the quote.
- Exits: SL = 1.5 x ATR, TP = 3.0 x ATR (L379-384; `compute_atr` L98-109 is Wilder-smoothed, `atr[-1]` includes the forming candle), both rounded to 2 dp; hard close of the position at the first poll in 16:00-16:15 ET (L317). No daily trade cap; after an exit the engine searches again if still inside the window.

### Gold: `griff_engine_gold.py` (symbol `XAUUSD`)
- Risk: `self.risk_pct = 0.005`, `contract_size = 100.0`, `tick_value = 1.0` (L70-74). Sizing `round(equity*risk / (sl_dist*1*100), 2)`, min 0.01 (L281-285).
- Range: at the 03:00 ET poll, `fetch_15m_candles(limit=28)`; range high/low over those 28 candles (L339-344).
- Entry 03:15-10:00 ET: `ask >= asian_high` -> BUY, `bid <= asian_low` -> SELL, market order (L347-360). ATR from `fetch_15m_candles(limit=20)` -> `compute_atr(candles, 14)[-1]` (L364-366; Wilder, seeded inside the 20-candle window). SL 1.5 x ATR, TP 3.0 x ATR (L370-375). One trade per day (`day_triggered`, L378-379; reset at 00:01 ET, L304). Hard close 16:00-16:15 ET (L309).

### Proxies and conventions (LIVE vs BACKTEST)

| Live behaviour | Backtest proxy |
|---|---|
| Polls the quote every 15 s (US100/Gold) / 30 s (BTC) | 1-minute bid bars. A level touched inside a minute counts as touched. |
| Market entries at ask/bid | Fill at the trigger level, or at the minute's open if the open already gapped past it. Spread charged separately as a cost. |
| Broker-side SL/TP | SL has priority over TP inside one minute; SL gapped through fills at the minute open (worse than SL); TP fills at the TP level, never better; a stop touched in the entry minute is a stop-out. |
| US100 `ask <= EMA(forming candle incl. current price)` | Algebraically identical to `price <= EMA(last completed candle)` because the EMA multiplier is < 1, so that is what is tested on each minute's low/high. |
| US100 EMA/ATR over the candle list MetaApi returns with no `limit` | 1000 candles assumed (SDK maximum; server default UNKNOWN). The seeded EMA20 and Wilder ATR14 converge long before 999 bars, so this does not change any trade. |
| US100 ATR includes the forming candle | Wilder step on the forming candle's partial OHLC up to the current minute. |
| Gold range from "last 28 x 15m candles" at the 03:00 poll | 27 completed candles plus the just-opened 03:00 candle, proxied by the 03:00 1-minute bar. |
| Gold ATR from the last 20 candles incl. forming | `GoldEngine.compute_atr` on 19 completed + the forming partial candle. |
| BTC 1H candles from the broker (CE(S)T server) | 1H bars from UTC-aligned 1m data; hour boundaries coincide. The 60-bar window spans data gaps the same way a "last 60 candles" fetch would. |
| BTC re-enters SEARCHING immediately after a stop-out and scans the last completed bar | Replayed: after a mid-bar exit the previous bar is scanned and any resulting pending lives only for the rest of that hour. |
| BTC 90% free-margin lot cap; broker max-volume limits | Not modelled (margin rates and per-symbol volume caps unknown). Largest sizes seen at Stack A: BTC 3.40 lots at ~$67k, US100 88.47 lots, Gold 3.63 lots. At FTMO crypto leverage the BTC cap would bind on tight-ATR setups, so BTC dollar PnL on those trades may be overstated. |
| BTC engine halts on $90k floor / 5% daily loss; FTMO 5%/10% rules | Not enforced. Breach counts are reported instead. |
| Hard close 16:00 ET | At the open of the first 1-minute bar in 16:00-16:14 ET. On early-close days with no such bar, the position carries with its broker SL/TP (as it would live) and is closed at the next 16:00-16:14 bar. |
| Equity for sizing = live account equity incl. floating PnL | Realized balance at entry time. |
| Drawdown / daily loss | Realized (closed-trade) only. Intraday floating drawdown is deeper than reported. |

BTC setup funnel (sanity check): 20,758 1H bars -> 2,418 inside bars scanned -> 1,421 blocked by ADX < 25 -> 997 pending orders placed -> 507 filled, 490 expired unfilled.

## What this does and does not say

- A +10% calendar month happened in 5 of 32 months at Stack A and 1 of 32 at Stack B on this feed. Stack A's +10% months come with a -36% realized drawdown, two realized days past FTMO's 5% daily limit, and four months worse than -10%; Stack B has none of those breaches and a +10% month only once.
- The combined edge is thin and uneven: BTC carries the result (+83.9R, nearly half of it one trade), Gold is marginal (+33.8R over 631 trades, +0.054R each), US100 as coded is negative (-47.1R, profit factor 0.91) at both stacks.
- Calendar months are a proxy for FTMO's rolling evaluation windows; realized-only drawdown understates intraday risk; the Dukascopy feed is not the FTMO feed; the US100 live `risk_pct` on the VM is UNKNOWN from this repo.
